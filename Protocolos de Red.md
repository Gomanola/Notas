**ARP**
Cuando una computadora nueva se une a una red de área local (LAN), recibirá una dirección IP única para usarla en la identificación y la comunicación.
Los paquetes de datos llegan a una puerta de enlace, o la parte del hardware de una red que permite que los datos fluyan de una red a otra, le pide al programa ARP que encuentre una dirección MAC que coincida con la dirección IP. La caché ARP mantiene una lista de cada dirección IP y su dirección MAC correspondiente. La caché del ARP es dinámica, pero los usuarios de una red también pueden configurar una tabla ARP estática que contenga direcciones IP y direcciones MAC.

**ICMP**
Es el mecanismo de control y diagnostico de IP que utilizan los dispositivos en red para comunicar sobre lo que pase a los paquetes que se encarga de mover el protocolo IP. Sirven usualmente para informar acerca de problemas de comunicación en la red. Se suele utilizar en dispositivos de red, como los enrutadores. El ICMP es crucial para informar de errores y realizar pruebas, pero también se puede utilizar en ataques de denegación de servicio distribuido (DDoS).

**OSPF**
Es un protocolo de entrutamiento de estado de enlace que utiliza un algoritmo matemático para determinar la mejor ruta a cada destino IP en la red. Es utilizado en redes de área amplia (WAN) y redes de área local (LAN). Fue diseñado para permitir que los routers intercambien información de enrutamiento y tomen decisiones sobre la mejor ruta para enviar paquetes de datos.
Utiliza un algoritmo de estado de enlace para calcular las rutas más cortas y eficientes en una red. Cada router OSPF mantiene una base de datos de estado de enlace que contiene información sobre los routers vecinos, las redes conectadas y los costos asociados a cada enlace. Esta información se intercambia entre los routers OSPF para construir un mapa completo en la red.

**TCP**
Es un protocolo que permite dispositivos comunicarse de manera confiable a través de una red. Asegura que los datos lleguen al destino correctamente y en el orden correcto, incluso si partes de la red son lentas o poco fiables.
Trabaja en la Capa de Transporte del modelo OSI y es una parte esencial del conjunto de protocolos TCP/IP utilizado para la comunicación por internet. TCP establece una conexión lógica entre el emisor y el receptor antes de que comience la transmisión de datos. Asegura que los datos se entreguen con precisión y en el mismo orden en que se enviaron utilizado acuses de recibo y números de secuencia. TCP detecta errores usando sumas de comprobación y retransmite paquetes perdidos o dañados para mantener la integridad de los datos.
TCP está orientado a la conexión, lo que significa que se debe establecer una conexión antes de que se envíen los datos. Esto se hace a través de TCP Handshake Process. Al momento de iniciar se usa un proceso llamado Connection Establishment (Three-Way Handshake): SYN (Synchronize), SYN-ACK (Synchronize) y ACK (Acknowledge). Y al momento de terminar la coneción se ejecuta Connection Termination (Four-Way Handshake): FIN (Finish), Ack (Acknowledge) y FIN (Finish) del receptor.

**UDP**
Es un protocolo de comunicación que se utiliza en Internet para transmisiones sujetas a limitaciones temporales, como la reproducción de video o las búsquedas en DNS. Acelera las comunicaciones al no establecer formalmente una conexión antes de transferir los datos. Esto permite que los datos se transfieran muy rápido, pero también puede hacer que los paquetes se pierdan en tránsito (y crear oportunidades para vulnerabilidades en forma de ataques DDoS). Como resultado, las aplicaciones que utilizan UDP deben ser capaces de tolerar errores, pérdidas y duplicaciones. Se suele utilizar en las comunicaciones sujetas a limitación temporal, en las que ocasionalmente es mejor dejar caer los paquetes que esperar. El tráfico de voz se envía mediante este protocolo, porque ambos están sujetos a limitación temporal y están diseñados para soportar cierto nivel de pérdida.

**SNMP**
Es un Protocolo de capa de aplicación que transmite datos de administración entre dispositivos de red. SNMP pertenece a la familia de Protocolo de control de transmisión / Protocolo de Internet (TCP/IP) y es uno de los protocolos de red más utizados para administrar y monitorear componentes de red en una variedad de industrias.

**DHCP**
Se utiliza para asignar dinámicamente direcciones de protocolo de Internet (IP) a cada host en la red de su organización. Em este significado DHCP, un host puede referirse a cualquier dispositivo que permita el acceso a una red. Algunos ejemplos incluyen computadoras de escritorio y portátiles. Asigna direcciones IP, así como máscaras de subred, direcciones DNS y otros datos esenciales a cada dispositivo que se conecta a la red.

**DNS**
Es el directorio telefónico de internet. Las personas acceden a la información en línea a través de nombres de dominio como nytime.com o espn.com. Los navegadores web interactuan mediante direcciones de Protocolo de Internet (IP). El DNS traduce los nombres de dominio a direcciones IP para que los navegadores puedan cargar los recursos de internet. Cada dispositivo conectado a Internet tiene una dirección IP única que otros equipos puedan usar para encontrarlo. Los servidores DNS suprimen la necesidad de que los humanos memoricen direcciones IP tales como 192.168.1.1 (en IPv4) o nuevas direcciones IP alfanuméricas, más complejas, tales como 2400:cb00:2048:1::c629:d7a2 (en IPv6).

**TELNET**
Es un protocolo de red que te permite conectarte y comunicarte con computadoras remotas a través de una red basada en el protocolo de control de transmisión/protocolo de internet (TCP/IP). Es como un terminal virtual, que te permite acceder a la interfaz de línea de comandos de un sistema remoto como si estuvieras físicamente presente. Telnet funciona estableciendo una conexión entre tu dispositivo local y el servidor remoto. Transmite tus pulsaciones de teclado y las recibe las respuestas del servidor, creando esencialmente un canal de comunicación basado en texto. Esta conexión no está encriptada, lo que la hace menos segura en comparación con alternativas como el Secure Shell (SSH).

**SSH**
Es un método para enviar comandos de forma segura a un ordenador mediante una red no segura. SSH utiliza criptografía para autenticar y encriptar las conexiones entre dispositivos. SSH también permite la tinelización, o redireccionamiento de puertos, que es cuando los paquetes pueden cruzar las redes que de otro modo no podrían cruzar. SSH se utiliza a menudo para controlar los servidores a distancia, para gestionar infraestructuras y para transferir archivos. Se ejecuta sobre el conjunto de protocolo TCP/IP, del que gran parte de Internet depende. El prottocolo TCP/IP transporta y entrega paquetes de datos. El uso de TCP es una de las diferencias entre SSH y otros protocolos de tunelización, algunos de los cuales utilizan en su lugar UDP, que es más rápido pero menos fiable.

**HTTP**
Constituye los cimientos de la red mundial, y se utiliza para cargar páginas web mediante enlaces de hipertexto. HTTP es un protocolo de capa de aplicación diseñado para transferir información entre los dispositivos conectados a la red, y se ejecuta sobre otras capas del conjunto de protocolos de la red. Un flujo típico sobre HTTP implica una máquina cliente que realiza una solicitud a un servidor, que a continuación envía un mensaje de respuesta. Una solicitud HTTP típica contiene: el tipo de versión de HTTP, una URL, un método HTTP, encabezados de solicitud HTTP, un cuerpo HTTP opcional.

**FTP**
Es un protocolo de red estándar utilizado para la transferencia de archivos de un host a otro a través de una red basada en TCP, como Internet. El FTP funciona abriendo dos conexiones que vinculan las computadoras que intentan comunicarse entre sí. Se designa una conexión para los comandos y respuestas que se envían entre los dos clientes, y el otro canal maneja la transferencia de datos. Durante una transmisión FTP, hay cuatro comandos utilizados por las computadoras, servidores o servidores proxy que se están comunicando. Estos son "enviar", "obtener", "cambiar directorio" y "transferir".

**NTP**
Se utiliza ampliamente para sincronizar un sistema con servidores de tiempo de Internet u otras fuentes, como un receptor de radio o satélite o un servicio de módem telefónico. Proporciona precisiones normalmente inferiores a un milisegundo en las LAN y hasta unos milisegundos en las WAN. Las configuraciones NTP típicas utilizan varios servidores redundantes y diversas vías de acceso de red para lograr una alta precisión y fiabilidad. Su objetivo es sincronizar el reloj local de tu máquina (fecha y hora) a través de la red mediante una máquuina de referencia, que llamaremos el servidor NTP. Utiliza el protocolo de transporte UDP y el puerto 123. Dentro de un sistema de información, permitirá que los diferentes equipos, es decir, computadoras, servidores, impresoras, enrutadoras o incluso cortafuegos permanezcan siempre a tiempo, evitando problemas, especialmente en el nivel de autenticación. Además, si se consultan registros, es preferible que estén correctamente marcados con la hora.

**MIME**
Es una forma estandarizada de indicar la naturaleza y el formato de un documento, archivo o conjunto de datos. Está definido y estandarizado en IETF RFC 6838. La autoridad de Números Asignados de Internet (IANA) es el organismo oficial responsable de realizar un seguimiento de todos los tipos de MIME oficiales. Los navegadores a menudo usan el tipo MIME (y no la extensión de archivo) para determinar cómo procesará un documento, por tanto, es importante que los servidores estén configurados correctamente para adjuntar el tipo MIME correcto al encabezado del objeto de respuesta.

**SMTP**
Se trata de un protocolo de comunicación que se utiliza para enviar y recibir mensajes de correo electrónico a través de Internet. Los servidores de correo y otros agentes de transferencia de mensajes (MTA) utilizan SMTP para enviar, recibir y reenviar mensajes de correo. En este modelo, el cliente o el servidor de correo electrónico del remitente actúa como cliente SMTP. Este cliente inicia una conexión con el servidor y transmite el correo electrónico con los detalles del destinatario, el asunto y el cuerpo. El servidor procesa este correo electrónico y determina el próximo servidor adecuado en función de la dirección del destinatario. El próximo servidor podría ser otro servidor SMTP en la ruta de transmisión o el destino final, es decir, el servidor de correo electrónico del destinatario. Una vez que el mensaje llega al servidor del destinatario, se envía a la bandeja de entrada del destinatario mediante un protocolo diferente, como POP o IMAP.

**BGP**
Es el servicio postal de internet. Cuando alguien echa una carta en un buzón, el servicio de correos procesa esa correspondencia y elige una ruta rápida y eficiente para entregar esa carta a su destinatario. Del mismo modo, cuando alguien envia datos a través de Internet, el BGP se encarga de buscar todas las rutas disponibles por las que podrían viajar los datos y elegir la mejor, lo que suele significar saltar entre sistemas autónomos. El BGP es el protocolo que hace que Internet funcione permitiendo el enrutamiento de datos. Cuando un usuario de Singapur carga un sitio web con servidores de origen en Argentina, el BGP es el protocolo que permite que esa comunicación se produzca de forma rápida y eficaz.
